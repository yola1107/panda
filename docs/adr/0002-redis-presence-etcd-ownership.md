# Redis 管在线索引，Etcd 管分片归属

在线索引与归属的一致性要求不同：前者用于投递定位，可短暂过时；后者决定谁能处理有状态业务，必须有唯一权威。
因此 Redis 存放在线索引，Etcd 存放业务域分片的归属；服务注册发现复用 Kratos。
在线索引不授予任何写权限。

## 后果

更新归属或在 RPC 上校验代次，不会自动阻止旧 Node 写业务存储。
关键业务写入必须由存储端验证 Fencing Token，或采用等效事务保护。
两个后端之间的更新不假设单事务，需要可恢复的流程。

## 未采用的方案

- 全部使用 Redis：在线索引的过时容忍度不足以承担归属权威。
- 自建统一元数据中心：重复建设 Kratos 注册发现与 Etcd 已有的能力。
