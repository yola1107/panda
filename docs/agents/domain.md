# Domain Docs

本仓库采用 single-context，所有服务共用一套领域文档。

## 文档位置与权威

- 术语表：[GLOSSARY.md](../../GLOSSARY.md)。
- 架构决策：[docs/adr/](../adr/)，文件名为 `<NNNN>-<slug>.md`。
- 规格与任务：`.scratch/<feature-slug>/`，约定见 [任务与规格约定](issue-tracker.md)。
- 设计讨论记录：[长连接设计讨论](../design/long-connection-discussion.md)，保存讨论来源与 M2/M3 未决项。

已确认的决策以术语表、ADR 和规格为准；讨论记录中与它们冲突的内容视为过时。

## 读取规则

探索代码、讨论领域概念或设计功能前：

- 读取术语表中的相关领域术语。
- 读取与当前工作相关的 ADR，以及对应功能的规格。
- 涉及尚未进入规格的长连接能力时，查阅设计讨论记录中的相关轮次与未决项。

## 使用规则

- 任务标题、设计讨论、测试名称等使用术语表定义的词汇，避免引入同义词漂移。
- 遇到缺失术语时，使用 `domain-modeling` 技能确认是否需要新增领域概念；需要时更新术语表。
- 提议与已有 ADR 冲突时，明确指出冲突的 ADR 和重新评估的理由。
