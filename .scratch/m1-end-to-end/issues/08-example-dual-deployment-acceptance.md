# 08: 示例应用与双部署验收

**What to build:** 用一个基于生成代码的示例应用演示一个逻辑服务的每种交互：登录、一个请求与应答、一个通知、一个由业务触发的主动推送。同一个示例分别以组合部署和分离部署运行，完成 M1 验收。规格见 [M1 规格](../spec.md)。

**Blocked by:** 02 TCP 入口；05 慢客户端断开；06 分离部署；07 路由声明与生成器

**Status:** resolved

- [x] 示例应用使用生成的 Handler 接口和注册代码，Go 参考客户端使用生成的客户端调用。
- [x] 示例主动推送通过生成的分发代码进入类型化回调，业务调用方不手写路由号或 payload 解码。
- [x] 示例提供组合部署和分离部署两种组装方式，配置用 Kratos Config 加载强类型配置。
- [x] 示例配置写明入口、编码器、最大包长、认证超时、空闲超时、执行超时、发送队列上限、单连接在途转交上限和 Node 执行上限的默认值。
- [x] 规格中接缝 A 的全部场景，在 TCP 和 WebSocket 两种传输、组合部署和分离部署下全部通过。
- [x] 同一逻辑服务使用 Protobuf 和 JSON 入口时，登录、请求、错误应答与类型化主动推送都正确；超时、取消、执行上限和迟到登录结果的场景均包含在验收中。
- [x] 涉及并发的包通过 `go test -race`。
- [x] README 说明如何运行示例的两种部署方式。
